# 길따라장따라 공공데이터 수집 계획

## 1 현재 보유 데이터

현재 CSV에는 광주·전남 119개 시장과 10,264개 인접 상가가 있으며 시장명, 시장 유형, 개설 주기, 취급 품목, 업종 분류, 주소, 좌표와 시장까지의 거리를 포함한다. SQLite DB에는 121개 시장과 10,264개 점포가 적재되어 있다.

현재 가장 큰 결손은 다음과 같다.

- 관광지·문화시설·행사 데이터가 `PLACE`에 적재되지 않았다.
- 장소 영업시간, 휴무일, 전화번호, 설명과 이미지가 부족하다.
- 주차장과 공중화장실 등 가족 여행에 필요한 편의시설이 없다.
- 시장 개설 주기의 예외 날짜와 임시 휴장 정보를 관리할 구조가 없다.
- 데이터 출처, 수집시각, 기준일과 검수시각이 점포별로 충분히 관리되지 않는다.

## 2 1차 수집 데이터

### P0 한국관광공사 국문 관광정보 서비스

목적: 시장 주변 관광지·문화시설·음식점·숙박·행사·이미지 후보를 채운다.

필요 항목: 콘텐츠 ID, 콘텐츠 유형, 제목, 주소, 좌표, 전화번호, 개요, 휴무일, 이용시간, 주차, 이미지, 수정일, 반려동물 동반 정보.

적재 대상: `place`, `local_event`.

활용 방법: 광주·전남 지역코드로 전체 동기화한 뒤 시장 좌표 기준 반경 검색에 사용한다. 추천 시 API를 매번 호출하지 말고 배치 적재 후 수정일 기반으로 갱신한다.

### P0 전국주차장정보표준데이터

목적: 자가용 여행자의 방문 실패를 줄인다.

필요 항목: 주차장명, 유형, 주소, 좌표, 주차구획수, 운영시간, 요금, 결제방법, 장애인 주차면, 관리기관, 전화번호, 기준일.

적재 대상: `place`의 `PARKING` 유형.

활용 방법: 시장별 최근접 주차장 3개를 사전 계산하고 거리, 운영시간, 요금을 함께 표시한다.

### P0 기상청 단기예보 조회서비스

목적: 여행일의 강수·기온·풍속을 코스와 주의사항에 반영한다.

필요 항목: 예보일시, 기온, 강수확률, 강수형태, 시간당 강수량, 풍속, 하늘상태.

적재 대상: 영구 마스터가 아니라 단기 캐시.

활용 방법: 여행 날짜가 예보 범위 안에 있을 때만 호출하고, 비가 오면 야외 장소 비중을 낮추고 실내 대체 장소를 제시한다.

### P1 전국문화축제표준데이터

목적: 시장 방문일에 겹치는 지역 축제를 코스 후보로 제공한다.

필요 항목: 축제명, 개최 장소, 시작일, 종료일, 내용, 홈페이지, 주소, 좌표, 기준일.

적재 대상: `local_event`.

활용 방법: 시장 반경과 여행 날짜가 모두 일치할 때만 노출한다. 오래된 파일을 그대로 추천하지 않고 기준일과 홈페이지를 표시한다.

### P1 전국공중화장실 및 지자체 개방화장실 데이터

목적: 가족·고령자·장시간 시장 이용자의 편의를 높인다.

필요 항목: 화장실명, 주소, 좌표, 개방시간, 남녀공용 여부, 장애인용·어린이용 시설, 관리기관, 기준일.

적재 대상: `place`의 `TOILET` 유형.

활용 방법: 전국 통합 데이터가 불완전하면 광주·전남 시군구 파일을 함께 수집한다. 시장 반경 내 개방시간이 맞는 시설만 표시한다.

### P1 소상공인시장진흥공단 전국 전통시장 현황

목적: 기존 시장 데이터의 점포 수, 개설 주기, 주차장·화장실 보유, 온누리상품권 사용 가능 여부를 보완한다.

필요 항목: 시장명, 시장유형, 주소, 점포 수, 개설 주기, 접근성, 주차장, 화장실, 온누리상품권, 기준일.

적재 대상: `market`.

활용 방법: 이름만으로 병합하지 않고 주소와 좌표를 함께 비교한다. 기존 시장 데이터보다 기준일이 최신인 필드만 갱신한다.

## 3 후순위 데이터

### P2 지방행정 인허가 음식점 데이터

음식점의 영업·폐업 상태 확인에는 유용하지만 주소 정규화와 중복 제거 비용이 크다. 첫 베타에서는 기존 상가 데이터와 TourAPI를 사용하고, 폐업 오류가 많을 때 추가한다.

### P2 전국도시공원·박물관·미술관·문화시설 표준데이터

TourAPI에 없는 공공시설을 보완하는 용도로 사용한다. 같은 장소가 여러 데이터셋에 중복될 수 있어 원천 ID와 병합 규칙이 먼저 필요하다.

### P2 무장애 관광 정보

가족·고령자 코스의 핵심 차별화로 발전시킬 수 있다. 출입구, 경사로, 장애인 화장실, 유모차·휠체어 대여처럼 실제 시설 필드가 있는 데이터부터 사용한다.

### P3 지역별 관광 수요와 다양성

추천 개인화보다 사업 분석과 지역 확장 우선순위에 적합하다. MVP 실시간 추천 데이터로는 사용하지 않는다.

### P3 버스·도시철도·대중교통

초기 MVP가 자동차 동선 중심이면 제외한다. 대중교통 코스를 출시할 때 정류장·시간표·환승 데이터와 함께 별도 기능으로 설계한다.

## 4 적재 원칙

1. 원본 파일을 Object Storage에 날짜별로 보관한다.
2. `raw`, `staging`, `service` 세 단계로 정제한다.
3. 원천 데이터의 ID를 잃지 않는다.
4. 이름만으로 장소를 병합하지 않는다.
5. 좌표가 없거나 기준일이 오래된 데이터는 추천 점수를 낮춘다.
6. 폐업·휴무 신고는 원본을 삭제하지 않고 상태와 검수 이력으로 관리한다.
7. 실시간 호출이 꼭 필요한 날씨·경로만 요청 시 조회하고 나머지는 배치 동기화한다.

## 5 첫 수집 순서

1. TourAPI 광주·전남 위치 기반 관광정보
2. 전국주차장정보 중 광주·전남
3. 전통시장 최신 현황과 기존 121개 시장 병합
4. 문화축제 중 광주·전남과 여행일 필터
5. 공중화장실 중 시장 반경 데이터
6. 단기예보와 추천 요청 시 캐시
