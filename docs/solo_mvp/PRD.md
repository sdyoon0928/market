# 길따라장따라 모바일 앱 PRD

문서 버전 1.0  
기준일 2026년 10월 28일

## 1 제품 정의

길따라장따라는 사용자의 여행 날짜, 출발지, 동행자, 체류 시간과 관심사를 바탕으로 해당 날짜에 이용 가능한 전통시장과 주변 관광지·맛집·카페를 실제 이동 가능한 순서로 구성해 주는 모바일 여행 플래너다.

첫 출시의 핵심은 AI 대화가 아니라 다음 세 가지다.

1. 해당 날짜에 방문 가능한 시장을 정확히 찾는다.
2. 시장과 주변 장소를 체류 시간 안에 이동 가능한 순서로 묶는다.
3. 주차·휴무·날씨·출처·최종 확인일을 보여 방문 실패를 줄인다.

## 2 문제 정의

- 시장, 관광지, 맛집, 주차장과 운영 정보가 여러 사이트에 흩어져 있다.
- 5일장은 개설 주기가 있어 일반 장소 검색만으로 방문 가능 여부를 알기 어렵다.
- 사용자는 장소 순서와 이동 시간을 직접 계산해야 한다.
- 기존 서비스는 전통시장을 코스의 중심 거점으로 다루지 않는다.
- 공공데이터는 갱신일과 품질이 서로 달라 그대로 추천에 사용하기 어렵다.

## 3 목표 사용자

### 우선 사용자

광주·전남에서 자동차로 반나절 또는 당일치기 여행을 계획하는 20대 후반에서 40대 여행자다. 친구 먹거리 여행을 첫 검증 시나리오로 사용한다.

### 후속 사용자

- 이동 부담이 낮은 코스가 필요한 가족 여행자
- 카페·산책·문화 공간을 묶으려는 커플 여행자

## 4 제품 목표와 제외 범위

### MVP 목표

- 사용자가 3분 안에 여행 조건을 입력하고 코스를 저장한다.
- 추천 결과의 모든 장소에 출처와 최종 확인일을 표시한다.
- 코스는 한 개 이상의 전통시장을 반드시 포함한다.
- 각 이동 구간에 예상 거리와 자동차 이동시간을 표시한다.

### MVP 포함

- 게스트 시작과 한 가지 소셜 로그인
- 자연어 및 선택형 여행 조건 입력
- 날짜에 맞는 시장 검색
- 주변 관광지·음식점·카페 후보 검색
- 시간대별 코스 생성
- 지도와 구간별 이동시간
- 일정 저장·수정·삭제
- 즐겨찾기
- QR 또는 수동 방문 기록
- 별점과 텍스트 리뷰

### MVP 제외

- 상인 가입과 사업자 승인
- 관리자 계정과 대시보드
- 예약, 결제, 정산, 쿠폰
- 시장 내부 평면 지도
- 실시간 혼잡도 보장
- 리뷰 자동 요약
- 사용자 간 커뮤니티
- 상시 위치 추적

## 5 대표 사용자 흐름

1. 사용자는 게스트로 시작하거나 로그인한다.
2. 날짜, 출발지, 체류 시간, 동행자와 선호를 입력한다.
3. 시스템은 추출한 조건을 보여주고 누락값만 요청한다.
4. 시스템은 해당 날짜에 열리는 시장을 먼저 필터링한다.
5. 시장 주변의 관광지·음식점·카페를 검색한다.
6. 지도 API로 구간별 이동시간을 계산한다.
7. 시간 제약을 만족하는 코스 후보를 최대 3개 생성한다.
8. 사용자는 장소를 교체하거나 삭제하고 일정을 저장한다.
9. 현장에서 방문을 기록하고 리뷰를 남긴다.

## 6 기능 요구사항

| ID | 기능 | 요구사항 | 우선순위 |
|---|---|---|---|
| FR-01 | 게스트 시작 | 로그인 없이 추천을 체험할 수 있어야 한다. 저장 시 로그인을 요청한다. | Must |
| FR-02 | 로그인 | 첫 버전은 네이버 또는 카카오 중 한 가지 OAuth만 지원한다. | Must |
| FR-03 | 조건 입력 | 날짜, 출발지, 체류 시간, 이동수단, 동행자, 선호를 입력한다. | Must |
| FR-04 | 조건 추출 | 자연어 입력을 구조화하고 불확실한 값은 사용자에게 확인한다. | Must |
| FR-05 | 시장 필터 | 개설 주기와 예외 일정을 이용해 여행일에 열리는 시장만 우선한다. | Must |
| FR-06 | 장소 검색 | 시장 반경과 카테고리, 운영시간, 선호 태그로 후보를 제한한다. | Must |
| FR-07 | 경로 계산 | 각 구간의 자동차 거리와 예상 시간을 지도 API로 계산한다. | Must |
| FR-08 | 코스 생성 | 체류 시간 안에서 시장을 포함하는 시간대별 코스를 최대 3개 생성한다. | Must |
| FR-09 | 근거 표시 | 추천 이유, 데이터 출처, 최종 확인일과 변동 가능성을 표시한다. | Must |
| FR-10 | 일정 편집 | 장소 교체·삭제·순서 변경 후 경로를 다시 계산한다. | Must |
| FR-11 | 일정 저장 | 로그인 사용자는 일정을 저장하고 다시 열 수 있다. | Must |
| FR-12 | 즐겨찾기 | 시장과 장소를 개별 저장한다. | Should |
| FR-13 | 방문 기록 | QR 또는 수동 선택으로 방문 시각을 기록한다. | Should |
| FR-14 | 리뷰 | 방문 장소에 별점과 텍스트 리뷰를 등록·수정·삭제한다. | Should |
| FR-15 | 정보 신고 | 폐업, 휴무, 잘못된 위치와 운영정보를 신고한다. | Should |

## 7 추천 규칙

- LLM은 장소를 새로 만들지 않는다.
- 후보는 반드시 DB에 존재하는 시장과 장소로 제한한다.
- 시장 개설일, 장소 운영시간, 위치와 상태는 구조화 데이터로 판정한다.
- 의미 검색은 장소 설명과 태그의 선호 적합도를 계산할 때만 사용한다.
- 코스 순서는 지도 API의 거리와 시간을 사용해 평가한다.
- 추천 설명은 확정된 후보와 계산 결과를 바탕으로 생성한다.
- 운영정보가 오래됐거나 비어 있으면 불확실성을 표시한다.

## 8 데이터 요구사항

모든 외부 데이터 레코드에는 `source_name`, `source_record_id`, `source_url`, `fetched_at`, `verified_at`을 저장한다. 동일 장소 병합은 이름만으로 하지 않고 좌표, 주소, 전화번호와 원천 ID를 함께 비교한다.

## 9 비기능 요구사항

- 일반 조회 API p95 응답시간은 1초 이내를 목표로 한다.
- 추천 생성은 10초 이내를 목표로 하고 진행 상태를 표시한다.
- 외부 API 실패 시 캐시된 데이터와 템플릿 코스를 제공한다.
- 비밀키와 DB 접속정보는 모바일 앱에 포함하지 않는다.
- 위치 권한은 사용 목적을 설명하고 거부해도 주소 입력으로 이용할 수 있게 한다.
- 계정 탈퇴와 개인정보 삭제 요청을 제공한다.
- 추천에 사용한 장소 ID, 점수, 모델 버전과 경로 결과를 기록한다.

## 10 핵심 지표

- 추천 완료율 80퍼센트 이상
- 3분 내 일정 저장률 60퍼센트 이상
- 추천 결과 저장률 40퍼센트 이상
- 추천 장소 출처 표시율 100퍼센트
- 운영정보 오류 신고율 5퍼센트 미만
- 방문 기록 후 리뷰 작성률 30퍼센트 이상

## 11 출시 기준

- 대표 입력 20건 중 18건 이상에서 유효한 코스를 생성한다.
- 휴무 가능성, 출처와 최종 확인일이 모든 장소 상세에 표시된다.
- 지도 API와 LLM API 장애 시 대체 흐름이 동작한다.
- 일정 저장·조회·수정·삭제가 실제 기기에서 동작한다.
- 개인정보 처리방침, 이용약관, 탈퇴 기능을 제공한다.
